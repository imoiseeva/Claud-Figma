## Контекст

- **Продукт:** SkillSprint — платформа cohort-based профессионального обучения (UX/UI, Product, Marketing, Analytics, AI Tools). Проектируем **student learning platform** (MVP, запуск ~3 месяца).
- **Аудитория:** взрослые профессионалы (beginner → middle, career switchers), учатся параллельно с работой, ценят структуру и mentor feedback. Тон: professional, modern, supportive — не школьная LMS.
- **Главный UX-принцип:** в любой момент студент понимает, где он находится и какое действие следующее.
- **Core flow (проектируется первым):** Dashboard → Course → Lesson → Assignment → Submission → Mentor Feedback → Continue Learning.
- **Модель данных:** Course → Cohort → Module → Lesson → Assignment; плюс Live Session, Resource, Feedback, Announcement.
- **Формат:** desktop-first responsive web. Без marketplace, соцсети, геймификации, сложного чата (см. бриф, разделы 44–45).
- **Прототип:** https://golden-crisp-536334.netlify.app
- **Figma:** https://www.figma.com/design/XJ3dZM6KtD3DHVtqND03k3/SkillSprint?node-id=0-1
- **Полный бриф:** [BRIEF.md](./BRIEF.md)

## Правила взаимодействия

1. Каждое решение дописывается в базу в том же ходу. Изменение, которое не записано, — не произошло.
2. Я правлю файл руками между ходами. Перед касанием любой ноды перечитай её и скажи, что изменилось. Никогда не возвращай «свою» версию поверх моей.
3. Сначала критика — потом перестройка. Диагноз с node ID и измеренными числами, а не «выравнивание выглядит странно».
4. Когда решение ветвится — покажи два-три варианта на клонах живых нод в Scraps, рядом. Не спорь о хексах словами.
5. Похожее уже есть? Открой референсную ноду, прочитай реальные отступы, размеры и стили — и делай под стать. Не строй по памяти.
6. Всё, что повторяется дважды, — компонент с вариантами.
7. После фиксации — никаких сырых значений: цвета и текст только через переменные и стили. Каждое изменение завершай проходом по несвязанным текстам и сырым филлам.
8. Auto-layout вместо спейсеров и ручных координат.
9. Возвращай ID созданных и изменённых нод.

### Расхождения прототипа с брифом — решены 2026-09-01 (см. «Принятые решения»)

- Мультикурсность — ядро UX: 2 активных курса, дашборд выбирает один next action между ними. **Принято как в прототипе.**
- Каталог внутри платформы («Мои курсы → Каталог», «Записаться») — **вне MVP, как в брифе §27**; в макетах секцию Каталог не проектируем.
- Push-уведомления в настройках профиля — **вне MVP, как в брифе §29**; каналы: in-app + email.
- Язык макетов — **английский** (прототип демо был на русском; терминология брифа — английская).
- Навигация: вместо Learn — «My Courses»; Home = «Что сейчас»; Profile через аватар в шапке — принято как в прототипе.
- Урок: табы «Заметки» и «Обсуждение», версионирование заданий, 6-шаговый пайплайн, «Попросить сдвинуть срок», «Работы когорты» — принято как в прототипе (детализация брифа, не противоречие).

## Принятые решения

- Модули открываются последовательно по расписанию cohort, но без жёстких prerequisites на просмотр (бриф §8).
- Оценка — качественный mentor feedback, без числовых grades (бриф §12).
- Overdue не блокирует обучение и не закрывает submission (бриф §13).
- Без встроенного мессенджера: фидбек внутри assignment + внешний канал для общих вопросов (бриф §14).
- Сначала проектируется core flow, остальные разделы после (бриф §50).
- **2026-09-01, владелец:** мультикурсность — ядро UX, у студента может быть **2 активных курса** одновременно; дашборд агрегирует их и выбирает один next action (как в прототипе, уточнение брифа §26).
- **2026-09-01, владелец:** язык макетов — **английский**.
- **2026-09-01, владелец:** каталог курсов внутри платформы — вне MVP (как в брифе §27); push-уведомления — вне MVP, только in-app + email (как в брифе §29). Эти элементы прототипа в макеты не переносим.
- **2026-09-01:** body-шрифт в Figma — **Inter** вместо Inter Tight (Inter Tight в Figma недоступен, Inter — ближайший из доступных; display Bricolage Grotesque и mono JetBrains Mono доступны).
- **2026-09-01:** типографическая шкала нормализована к целым px (в прототипе дробные кегли 12.5/13.5/14.5 от fluid-вёрстки) — размеры только из шкалы стилей.
- **2026-09-01:** структура файла — 3 страницы (лимит Starter-плана): 01 System (foundations+компоненты), 02 Core Flow, Scraps.
- **2026-09-01, владелец:** body-шрифт — **Instrument Sans** (замена «дефолтного» Inter; ближе по духу к Inter Tight прототипа, парится с Bricolage). Display и mono без изменений.
- **2026-09-01, владелец (копирайт):** средник «·» не используется для склейки фраз-предложений (только в дата-метах вида «Cohort 12 · Week 3»); в EventRow meta не дублируем время — оно уже в левой колонке (осталось «курс · день»).

## Грабли Figma

_Дописывать всё, на что наткнёмся._

- Фрейм перестал hug'ать содержимое — ищи обёртку: Figma при перетаскивании тихо вставляет лишний Frame.
- Таблицы и списки: фиксированные колонки с выравниванием, не SPACE_BETWEEN — иначе цифры пляшут по строкам.
- Иконку нельзя растягивать под слот — строй близнеца нужного размера и поправь толщину обводок.
- Цвет не переживает swap иконки: после каждой замены перепривяжи заливки и обводки к стилям.
- Починил мастер — проверь инстансы: их overrides остаются сломанными.
- Секции не растут сами: расширь секцию до того, как класть в неё новое.
- Не масштабируй текст rescale'ом — выставляй fontSize, иначе появятся размеры мимо шкалы.
- Starter-план: максимум **3 страницы** в файле и **1 режим** в коллекции переменных — dark mode и разбиение на много страниц недоступны без апгрейда.
- **Inter Tight в Figma недоступен** — body везде Inter. У JetBrains Mono нет начертания SemiBold — для w600 использовать Medium (или Bold).
- Стиль Inter — «Semi Bold» с пробелом, не «SemiBold» (у Bricolage наоборот: «SemiBold» слитно).
- Starter-план лимитирует и **количество вызовов Figma MCP** — при активной стройке квота кончается за один длинный сеанс; работать крупными шагами (меньше промежуточных скриншотов), состояние вести в PROJECT.md, чтобы продолжать после сброса.
- Скриншот ноды по умолчанию рендерит и перекрывающий контент соседей — для проверки компонента использовать `contentsOnly: true`; «артефакты» на превью проверять попиксельно, прежде чем чинить.
- Прозрачность пейнта, заданная при создании через spread (`{...paint, opacity}`), может не доехать: инстансы, созданные до фикса мастера, держат старый пейнт с opacity 1 даже без overrides. Чинить: выставить `fills[0].opacity` явно на мастере И проверить/перезаписать существующие инстансы.
- Дети инстансов не ресайзятся — процент прогресс-бара нельзя задать шириной Fill на инстансе. Решение: вариантная ось Percent + Fill на SCALE-констрейнте.
- Смена `fontName` в text style сбрасывает текстовые prop-оверрайды вложенных инстансов (лейблы кнопок вернулись к дефолту) и может оставить инстанс в рассинхроне «API говорит одно, рендер другое». Лечение: перезадать значения props на мастерах И явно на живых инстансах, проверять `text.width` против ширины кнопки.
- Запись fills во вложенный (2-й уровень) инстанс может молча не примениться и оставить залипший оверрайд; `resetOverrides()` чистит его, но сбрасывает и swap варианта с лейблом — после сброса свапнуть и проставить пропсы заново.
- Полупрозрачные плашки (opacity пейнта или альфа COLOR-переменной) поверх тёмного рендерятся ненадёжно — для таких случаев пре-блендед непрозрачный цвет в переменной (см. bg/nav-active).
- Любая правка текстового свойства **после** привязки стиля (напр. `textCase = 'UPPER'`) отвязывает text style. Свойство должно жить в самом стиле (Overline теперь UPPER) — привязывать стиль последним шагом и проверять аудитом `textStyleId`.
